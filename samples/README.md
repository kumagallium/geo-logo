# 手描きの計画

**推測を止めるための実物。** ここにあるのは人が手で書いた計画で、生成物では
ありません。「いまの語彙で何が書けて何が書けないか」を確かめるために、
目標にしたい水準のマークを題材ごとに手で起こしたものです。

ここまでに見つかった壁は、ほぼ全部この手描きから出ました。合成形
（ヴェシカ・四肢）に制約を張るとソルバーが引き剥がすこと、`grip: center` が
散らす反復を飲み込むこと、混み合いの逃がし方が一律だったこと、円弧の当てはめ
が密なラフを潰すこと——どれも眺めていて気づいたのではなく、**同じ絵を出そう
として届かなかった**ことで分かりました。

```bash
pnpm tsx scripts/sheet.ts tmp/s.png samples/*.json   # 並べて測る
pnpm tsx scripts/draft.ts samples/bear-sketch.json b # ラフを直す（輪郭方式のみ）
pnpm tsx scripts/render.ts samples/c-sakura.json s   # 1 件を全診断つきで
```

| ファイル | 経路 | 何のために置いてあるか |
| --- | --- | --- |
| `a-sunflower.json` | 関係 | 放射の花弁 26 枚。反復の密度と、囲いの構造 |
| `b-pegasus.json` | 関係 | **書けなかった例。** 紋章の曲線と渦は円と接線では届かない |
| `c-sakura.json` | 関係 | 五弁の桜と剣。紋の構造が一致した例 |
| `d-jackal.json` | 関係 | **書けなかった例。** 直線の面だけで組む形は円弧では出せない |
| `e-rope.json` | 関係 | 縄の輪と梅。撚りの傾きが表現できていない |
| `jackal-sketch.json` | 輪郭 | 同じ題材をラフで描いたもの。関係方式との差が出る |
| `bear-sketch.json` | 輪郭 | 熊。キーラインを入れる前の版。境目の白を手で引いている |
| `bear-profile.json` | 輪郭 | 熊の横向き。丸い耳と奥の脚をキーラインで分ける |
| `bear-face.json` | 輪郭 | 熊の正面。鼻面をキーラインで浮かせる。輪郭方式の到達点 |
| `fish-sketch.json` | 輪郭 | 角の保持の検査に使っている（尾の切れ込み） |
| `panda-figure.json` | 関係 | 入れ子の目・四肢・キーラインが全部入った例 |
| `clover-figure.json` | 関係 | 反復の混み合い（子が親より大きい側）の検査 |

**誤検出の対照としても使ってください。** 判定を足すときは、まずここへ当てて
「壊れていないものを咎めないか」を確かめること。実際、島の判定はこれで
2 度直しました。

## 熊で分かったこと（11 世代・約 45 案）

- **キーラインで浮かせた丸い耳が熊にする。** 耳を体の輪郭の凸で描くと、円弧の
  当てはめが角に畳んで角（つの）になる。別輪郭の円としてキーラインで重ねると、
  丸さがそのまま残る。これ 1 つで「牛に見える」が「熊に見える」に変わった
- **手足に `outline` を付けてはいけない。** 縁取りは部品の全周を回るので、突き
  出した部品は必ず切り離される（`grip` を変えても直らない。深く食い込ませても
  白が一周するため）。分けたい部品にだけ付けること
- **点の少ない小さな輪郭は粗くなる。** 許容誤差は基準点数（14）からの比で緩む
  ので、目や鼻を 6 点で描くと粗い多角形になる。小さくても 12〜14 点置く
- **輪郭方式は囲い（環）の中に塊を置けない。** 抜きが必ず最後に効くので、環の
  内側の抜きが中身まで消す。「丸に熊」は関係方式で組むこと
- **立ち上がった姿勢は輪郭方式では出せなかった。** 四肢を 1 本の輪郭に含めると
  articulation が消え、別輪郭にすると浮く。関係方式（`limb`）の領分
